Designing Ephemeral Document Delivery with FastAPI and Android FLAG_SECURE

Threat modeling client-side document leaks: why encrypted transport alone is insufficient, how short-lived decryption keys work on mobile clients, and where OS protections stop.

Standard file-sharing links solve confidentiality in transit via TLS, then immediately lose control the moment the recipient's browser downloads the file to ~/Downloads. In enterprise workflows—sharing unreleased schematics, financial drafts, or internal audit documents—the leak vector is rarely a man-in-the-middle attack; it is trivial local persistence and screen capture.

For our Secure Enterprise File Viewer, we paired a FastAPI backend with a dedicated Android client to narrow that exposure window as tightly as mobile OS primitives allow.

1. Eliminating Persistent Plaintext on the Client

If an Android app writes a decrypted PDF or image to shared storage—or even unencrypted app cache—a rooted device or ADB backup can extract it. Our pipeline avoids plaintext disk writes:

  • The FastAPI server encrypts document chunks per session using an ephemeral symmetric key derived after validating the client's device-bound authorization token.
  • The Android client decrypts pages directly into an in-memory buffer and renders bitmaps onto a surface view, zeroing buffers when the activity pauses or the session TTL expires.

2. Payload Integrity and Tamper Detection

Encryption alone does not prevent replay or parameter tampering. Every API request carries a signed timestamp, device fingerprint hash, and single-use nonce validated by FastAPI middleware before touching storage:

# Simplified request verification flow in FastAPI
def verify_session_request(token: str, device_sig: str, nonce: str, ts: int):
    if abs(time.time() - ts) > MAX_CLOCK_SKEW_SEC:
        raise HTTPException(status_code=401, detail="Expired request window")
    if nonce_store.seen(nonce):
        raise HTTPException(status_code=409, detail="Replay detected")
    session = db.get_active_session(token)
    if not session or not hmac.compare_digest(session.device_sig, device_sig):
        raise HTTPException(status_code=403, detail="Device binding mismatch")
    nonce_store.record(nonce, ttl=MAX_CLOCK_SKEW_SEC * 2)

3. Blocking Screen Capture with FLAG_SECURE

On Android, setting WindowManager.LayoutParams.FLAG_SECURE on the viewer window instructs SurfaceFlinger to treat the window content as secure—blocking standard screenshots, screen recording APIs, and recent-apps thumbnail previews.

Honest threat boundary: Software controls cannot stop an external physical camera pointed at a screen. The goal of combining ephemeral keys, device-bound tokens, and FLAG_SECURE is eliminating casual digital redistribution and forensic file recovery while maintaining auditability over who viewed which page and when.
